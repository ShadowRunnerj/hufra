# حُفرة — برنامج تعريب ألعاب الكمبيوتر

## ⚡ أسهل طريقة: ملف واحد يسوي كل شي (على Windows)

شغّل `RUN-ME.bat` بس (دبل كليك عليه)، وهو يسوي التالي لحاله بدون ما تدخل أي أمر:
1. يتأكد من .NET SDK و Inno Setup، ويثبّتهم تلقائياً لو ناقصين (عبر winget)
2. يبني البرنامج
3. يغلّفه كملف تنصيب
4. يثبّته ويفتحه لك تلقائياً

> ⚠️ **صراحةً وياك:** هذا مو "افتح وخلاص" 100% — أول تشغيل ممكن ياخذ عدة دقائق
> (تحميل أدوات)، وويندوز غالباً بيطلع لك تحذير أمني (SmartScreen) لأنه ملف
> جديد وغير موقّع رقمياً؛ اضغط "More info" ثم "Run anyway" لأنه ملف بنيته أنت.
> لو ثبّت .NET SDK لأول مرة، ممكن يطلب منك تسكّر النافذة وتشغّل الملف
> مرة ثانية (مشكلة معروفة بتحديث PATH بويندوز، مو خطأ بالسكربت).
> بعد أول مرة ناجحة، أي تعديل بالكود يحتاج بس تعيد تشغيل نفس الملف.

## 🔧 لو تبي تتحكم بالخطوات بنفسك (اختياري)

**عندك 3 خيارات حسب الشكل اللي تبيه:**

### أ) ملف Setup احترافي (`Hufra-Setup.exe`) — نفس شكل أي برنامج تحمّله عادةً
هذا يعطيك معالج تثبيت كامل (Next, Next, Finish) مع أيقونة، اختصار سطح مكتب،
وقائمة ابدأ — بالضبط زي أي تطبيق تنزّله من الإنترنت.

1. ثبّت [.NET 8 SDK](https://dotnet.microsoft.com/download) مرة وحدة (لو مو مثبت)
2. ثبّت [Inno Setup](https://jrsoftware.org/isdl.php) مرة وحدة (مجاني، أداة تغليف برامج)
3. شغّل `publish.bat` (يبني البرنامج نفسه)
4. شغّل `build-installer.bat` (يغلّفه كملف تنصيب)
5. النتيجة النهائية: `Output\Hufra-Setup.exe` ← **هذا هو الملف اللي توزّعه على أي جهاز**

### ب) ملف exe واحد بدون معالج تثبيت (أسرع لو تبي تجربة سريعة لنفسك فقط)
1. ثبّت .NET 8 SDK (خطوة 1 أعلاه)
2. شغّل `publish.bat` فقط
3. النتيجة: مجلد `dist\` كامل — شغّل `dist\Hufra.exe` مباشرة بدون تنصيب
   (لو تبي تنقله لمكان ثاني، انسخ مجلد `dist` كامل، مو ملف Hufra.exe لحاله)

### ج) تجربة سريعة أثناء التطوير (يحتاج .NET SDK مثبت باستمرار)
شغّل `run-dev.bat`، أو من الطرفية:
```powershell
dotnet run --project Hufra.App
```

هذا هو الأساس (Foundation) الأول للمشروع حسب المواصفات. يبني بـ **WPF (.NET 8)**
لأنه يدعم RTL بشكل أصلي ومناسب لتطبيق Windows احترافي.

> ⚠️ **مهم**: هذا المشروع WPF ويحتاج Windows للبناء والتشغيل (`net8.0-windows`).
> لم يتم بناؤه أو اختباره فعلياً هنا (بيئة التطوير الحالية Linux)، فراجع الكود
> بعناية عند أول build ولا تتفاجأ لو احتجت تصليحات بسيطة (أسماء namespace،
> مراجع NuGet، إلخ) — الكود مكتوب بعناية لكنه غير مُختبر على مترجم حقيقي.

## وش يشتغل فعلياً في هذا الإصدار

✅ الواجهة كاملة: التنقل، الهوية البصرية، RTL، الشعار
✅ اختيار مجلد لعبة يدوياً (`OpenFolderDialog`)
✅ اكتشاف ألعاب Steam المثبتة تلقائياً (قراءة `libraryfolders.vdf` + `appmanifest_*.acf`)
✅ "مكتبة ألعاب أخرى" — تحدد أي مجلد رئيسي يحتوي عدة ألعاب (مثل `C:\Vault Games`) مرة وحدة،
   يُحفظ بالإعدادات، والبرنامج يسرد كل الألعاب جواه تلقائياً بنفس طريقة Steam
✅ دعم اختيار ملف لعبة **مضغوط (ZIP)** مباشرة — البرنامج يفك الضغط تلقائياً بالخلفية بدون
   ما تحتاج تفكه يدوياً قبل، ويكمل الكشف والاستخراج على المجلد المستخرج مباشرة
   (صيغة .zip بس حالياً؛ .rar و.7z تحتاج مكتبة خارجية إضافية غير مضمّنة بعد)
✅ كشف محرك اللعبة تلقائياً (بصمات ملفات لكل من: Unity, Unreal, Godot, GameMaker, RPG Maker, Ren'Py)
✅ استخراج وتطبيق نصوص من ملفات JSON/txt الحرة لخمس محركات: **Unity, Godot, Unreal Engine,
   RPG Maker (MV/MZ), Ren'Py** (المنطق المشترك بـ `LooseTextExtractor.cs` بدل تكراره بكل Adapter؛
   Ren'Py له منطق مخصص بصياغة .rpy نفسها بدل الفاحص العام)
✅ دعم **محركات خاصة (custom)** غير معروفة الاسم عن طريق التعرف على نمط ملفات XML الشائع
   `<string id="..." text="..." />` (`XmlLocalizationAdapter.cs`) - يشتغل مع ألعاب مثل
   Mount & Blade II: Bannerlord وأي لعبة ثانية تستخدم نفس صيغة الترجمة
✅ شرائح حالة الدعم بواجهة "التعريب" — توضح بصراحة أي محرك مدعوم فعلياً وأيها لسا قيد التطوير
✅ استخراج وكشف المحرك يشتغلوا بالخلفية (async) بدل تجميد الواجهة، مع أولوية لمجلدات الترجمة
   المعروفة (Languages, Strings...) بدل فحص كل ملفات اللعبة - أسرع بمراحل بالألعاب الكبيرة
✅ زر "▶ تشغيل اللعبة" — يحدد الملف التنفيذي الرئيسي تلقائياً (`GameLauncher.cs`) ويشغّله، مع استبعاد
   الملفات المرافقة الشائعة (crash handlers, anti-cheat, installers...)
✅ ترجمة تلقائية بجودتين: **Claude (ذكاء اصطناعي)** لو المستخدم حط مفتاح Anthropic API بالإعدادات
   (دقة أعلى بكثير، يفهم سياق الألعاب، يحافظ على المتغيرات البرمجية بدقة، يترجم دفعات كاملة بطلب
   واحد)، أو **Google Translate المجاني** تلقائياً كاحتياطي بدون مفتاح (`TranslationService.cs`)
✅ صفحة الإعدادات فيها إدخال/حذف مفتاح Anthropic API، ويظهر بوضوح بصفحة "التعريب" أي مزوّد نشط حالياً
✅ شاشة مراجعة (DataGrid) تعرض النص الأصلي جنب الترجمة، قابلة للتعديل، مع مربع تفعيل لكل نص
✅ **مسرد اتساق تلقائي** — قبل ترجمة أي دفعة نصوص، Claude يفحص عيّنة ويستخرج أسماء الشخصيات/الأماكن
   المتكررة ويثبّت ترجمة موحّدة لها، فتُستخدم بنفس الشكل بكل مكان باللعبة (لا يترجم نفس الاسم
   بطريقتين مختلفتين بين دفعة وأخرى)
✅ شريط تقدّم مرئي أثناء الترجمة (بالإضافة للنص الرقمي)
✅ **ملف شخصي محلي** — أيقونة أعلى يمين النافذة (اسم + صورة تختارها من جهازك)، بدون أي حساب
   أو سيرفر أو إنترنت. تضغط عليها يطلع سجل كل الألعاب اللي طبّقت عليها ترجمة، بتاريخ كل عملية.
   **ملاحظة صريحة:** هذا مو "تسجيل دخول" حقيقي (يوزر/باسورد يتحقق منه سيرفر) — هذا محلي 100%
   على جهازك بس، لأن تسجيل دخول فعلي يحتاج سيرفر وقاعدة بيانات مستضافة، وهذا خارج نطاق تطبيق
   سطح مكتب موزّع بدون خادم خلفي.
✅ تطبيق الترجمة فعلياً على ملفات JSON عبر `System.Text.Json.Nodes`

## وش لسا ناقص (بالترتيب المقترح للتطوير القادم)

1. **نظام BackupManager مشترك** — نسخ احتياطي قبل أي تعديل، وإمكانية استرجاع (بند 12 بالمواصفات).
   لازم يكون طبقة عامة تستخدمها كل الـ Adapters، مو مكرر بكل واحد.
2. **أمان مفتاح API** — يُحفظ حالياً كنص عادي بملف `%AppData%\Hufra\settings.json` بدون تشفير.
   مقبول لأداة شخصية، لكن تحسين لاحقاً ممكن عبر Windows DPAPI (`System.Security.Cryptography.ProtectedData`).
3. **شاشة مراجعة النصوص** — موجودة الآن (DataGrid قابل للتعديل + تحديد الكل)، لكن بدون بحث/فلترة
   للقوائم الطويلة (ألعاب RPG قد تحتوي آلاف الأسطر) - يحتاج تحسين للتعامل مع أحجام كبيرة.
4. **الشعار الفعلي** — حالياً حرف "ح" برمجي داخل دائرة XAML، بدون ملف تصميم احترافي (SVG/PNG).
5. **نظام التحديث** — غير موجود حالياً (كان مبني بالكامل ثم أُزيل بطلب صاحب المشروع، لأنه
   يحتاج استضافة ملف `version.json` على حساب GitHub شخصي - خطوة لازم صاحب البرنامج يسويها بنفسه).
6. **GameMaker** — آخر محرك من الستة بدون دعم استخراج حقيقي (data.win صيغة ثنائية بالكامل).
7. **حزم الألعاب المعبأة بالكامل** (Unity resources.assets، Godot .pck، Unreal .pak) — تحتاج
   مكتبات تحليل ثنائي متخصصة لكل صيغة. الحل البديل المؤقت لـ Unity تحديداً هو مشروع
   **ArabicUnityFix** (حقن وقت التشغيل عبر BepInEx) من محادثتنا السابقة.

## قرارات تقنية اتخذتها ولازم تعرفها

- **OpenFolderDialog**: استخدمت النسخة الأصلية المدمجة في .NET 8 WPF
  (`Microsoft.Win32.OpenFolderDialog`)، مو مكتبة خارجية.
- **قراءة VDF (ملفات Steam)**: استخدمت Regex بسيط بدل مكتبة VDF كاملة، كافٍ
  للحقول المطلوبة حالياً (`name`, `installdir`, `path`). لو احتجت لاحقاً حقول
  أعمق (DLC، قوائم تشغيل) يفضّل التبديل لمكتبة VDF متخصصة.
- **استخراج نصوص JSON بـ Unity**: يمشي على شجرة JSON كاملة ويستخرج كل
  `string` تبدو كنص عرض (مو مفتاح/مسار برمجي)، عبر فلترة بسيطة في
  `LooksLikeDisplayText`. هذا الفلتر مبدئي وبيحتاج تحسين مع تجربة ألعاب حقيقية
  (قد يفوّت نصوص أو يلقط أشياء زايدة).

### الإصدار 1.7.0 — التعريب الحقيقي والسلامة
- **نسخ احتياطي مركزي:** قبل أي تعديل تُحفظ الأصول في `%AppData%\Hufra\backups` مع بصمة SHA-256. الأولى هي المرجع دائماً. زر «استعادة الملفات الأصلية» يعيد كل ملف ويتحقق من بصمته ويحذف ما أضافه حُفرة.
- **تحقق بعد التركيب:** يقارن بصمة الملفات قبل/بعد، ويعيد قراءة الملفات ليتأكد أن النصوص المترجمة موجودة فيها فعلاً. النتيجة: نجاح / جزئي / فشل. لا يُعلن نجاح لو لم يتغيّر أي ملف.
- **الخطوط:** يقرأ جدول `cmap` داخل ملفات TTF ليعرف فعلياً هل الخط يحتوي الحروف العربية، ويستبدل غير الداعم بـ Noto Sans Arabic (ترخيص OFL، مرفق في `Fonts/`) بنفس الاسم، مع نسخة احتياطية.
- **تنبيه الملفات المحزومة:** يكتشف `resources.assets` و`.bundle` و`.pak/.utoc` و`.pck` و`data.win` و`.xp3/.rpa` ويحذّر أن نصوصها لا يمكن تعديلها حالياً.

**حدود صريحة:** نصوص وخطوط Unity وUnreal وGodot غالباً داخل ملفات محزومة، وهذه لا يعدّلها حُفرة بعد؛ يعمل مع ما كان منها ملفات حرة (JSON/CSV/TXT/PO/Properties/YAML/RPY/KS...) وألعاب Paradox وRPG Maker وRen'Py. التحقق يخص محتوى الملفات؛ شكل الحروف داخل اللعبة لازم يُشاهد بتشغيلها.
